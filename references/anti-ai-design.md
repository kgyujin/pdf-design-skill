# AI 티 나는 디자인 피하기

생성형 도구가 만든 문서에서 반복적으로 보이는 시각 패턴이다. 하나하나는 문제가 없어도, 여러 개가 겹치면 "템플릿으로 찍어낸 문서"처럼 보인다.
pdf-design의 기본 스타일은 아래 패턴을 쓰지 않도록 만들어져 있다. 문서를 작성할 때도 `<style>`이나 마크업으로 이 패턴을 다시 넣지 않는다.
`check` 명령이 일부를 자동으로 경고한다(표의 "자동" 열).

## 금지·자제 패턴

| 패턴 | 왜 AI 티가 나는가 | 대신 할 것 | 자동 |
|---|---|---|---|
| 모든 제목 위의 대문자·자간 넓은 라벨 ("EXECUTIVE SUMMARY") | 내용과 상관없이 반복되는 장식 | 라벨은 표지·섹션 구분처럼 필요한 곳에만. 문장형 소문자, 보조색 | ✓ (슬라이드 과반에 라벨) |
| `01 02 03` 처럼 0을 붙인 번호 | 랜딩 페이지 템플릿의 전형 | `1 2 3` 또는 `1.` | ✓ |
| 번호·아이콘을 색 채운 원·알약 안에 넣기 | 장식용 칩 | 숫자만 쓰고 굵기로 구분. Figure 위치 핀(`.pin`)만 예외 | ✓ |
| 카드·콜아웃·제목 왼쪽의 굵은 포인트색 세로 바 | 대시보드 UI 관습 | 위아래 얇은 룰, 배경 톤, 들여쓰기 | ✓ |
| 표지·빈 공간의 장식 도형(원, 링, 블롭, 사각 점, 도트 그리드) | 의미 없는 채움 | 여백과 타이포그래피로 구성 | ✓ (문서 스타일) |
| 그라데이션, 글로우, 그림자, 유리 효과 | 화면 UI 스타일이 인쇄물에 들어옴 | 단색 면, 얇은 선 | ✓ |
| 알약 모양(`border-radius: 999px`) 태그·배지 남용 | 앱 UI 관습 | 2pt 정도의 작은 모서리, 테두리만 | ✓ |
| 같은 크기 카드 3개 나열("P0/P1/P2", "원인 1/2/3") | 내용 구조와 무관한 격자 | 번호 목록, 표, 비교 레이아웃 | 수동 |
| 큰 숫자 타일 대시보드(색 배경 KPI 카드) | 모든 보고서를 대시보드처럼 만듦 | 얇은 룰 위의 숫자, 꼭 필요한 지표만 | 수동 |
| 강조색으로 칠한 불릿·번호·라벨·링크·태그 | 강조가 강조가 아니게 됨 | 강조색은 한 페이지에 한두 곳(핵심 수치, Figure 강조) | 수동 |
| 인디고·보라 계열 기본색(#3b5bdb, #6366f1 등) | 생성형 UI의 기본 팔레트 | 흑백 중심(`graphite`) 또는 주제에 맞는 색조 | 수동 |
| 이모지·아이콘을 제목이나 목록 앞에 붙이기 | 장식용 기호 | 쓰지 않는다 | ✓ |
| 문장 사이에 줄표(—)를 반복하는 문구 | 생성형 문체의 대표 특징 | 쉼표, 마침표, 괄호 | ✓ (문단 2개 이상) |
| 문서 스타일에서 HEX 색을 직접 지정 | 팔레트와 어긋난 임의 색 | `var(--accent)` 등 토큰 | ✓ |
| "핵심 포인트", "Key Takeaways" 같은 박스를 페이지마다 반복 | 내용 없는 형식 | 콜아웃은 문서 전체에서 꼭 필요한 곳에만 | 수동 |

## 대신 지향하는 것
- 위계는 크기·굵기·여백으로 만든다. 색과 박스는 마지막 수단이다.
- 선은 얇게(0.5~1pt), 색은 먹색·회색 중심으로 쓴다. 강조색은 데이터와 결론에만 쓴다.
- 레이아웃은 내용 구조에서 나온다(순서 → 번호 목록, 비교 → 표·2열, 수치 → 표·차트).
- 문구는 구체적인 명사와 수치로 쓴다. "혁신적인", "강력한", "원활한" 같은 수식어를 쓰지 않는다.

## 점검 순서
1. `check` 결과에서 "AI 티" 경고를 모두 해결한다.
2. 미리보기를 보고 위 표의 "수동" 항목을 확인한다. 특히 같은 모양의 카드 반복과 강조색 과다를 본다.
3. 페이지를 흑백으로 떠올려 본다. 색을 빼도 위계가 읽히면 통과다.
