# PDF 디자인 규칙

HTML을 작성하기 전에 읽고, 렌더링 후 체크리스트로 점검한다.

## 1. 먼저 정할 것
- **사용자 지시 우선**: 제목 형식, 색상, 참고 디자인, 원본 이미지 사용 조건을 먼저 따른다.
- **문서와 발표 구분**: A4는 읽는 밀도, 발표는 먼 거리에서 읽히는 크기 대비와 페이지 간 변화가 중요하다. 아래 A4 수치를 발표 덱에 그대로 적용하지 않는다.
- **독자와 목적**: 누가 읽고, 무엇을 결정하는가. 표지는 제목·부제·발표 정보·주제 이미지로만 구성하고 결론은 본문에서 다룬다.
- **형식**: 여러 쪽에 걸쳐 읽는 문서는 `report`, A4 한 장은 `onepager`, 발표나 화면 공유용은 `deck`.
- **디자인**: 사용자가 정한 축만 바꾸고 나머지는 유지한다. 정하지 않았으면 `palettes.md`의 명시 설정 > 저장 선호 > 주제 자동 선택 > neutral 순서를 따른다.

## 2. 타이포그래피
- A4 본문 크기와 행간은 밀도 옵션이 정한다(기본 10pt·1.65). 본문을 9pt 아래로 줄이지 않는다. 캡션·메타만 7.5~8.5pt를 쓴다.
- 기본 폰트는 고딕(Pretendard)이다. 바탕체·명조체는 사용자가 명시적으로 요청했을 때만 `--font serif`/`serif-all`로 쓰고, 폰트는 고운바탕이다. 문서에서 `font-family`를 직접 지정하지 않는다.
- 크기 단계는 `--fs-*` 토큰만 쓴다. 한 페이지에 쓰는 크기는 4단계 이하로 둔다.
- 굵기는 스타일 토큰(`--head-weight`)을 따른다. 발표는 제목·핵심 숫자·설명 크기를 분명히 나누고 2~3개 주제·데이터 색으로 역할을 구분한다. 그룹 색과 강조색을 혼동하지 않는다.
- 한글 줄바꿈을 위해 `word-break: keep-all`을 유지한다(core.css에 이미 있다).
- 숫자 열은 `tabular-nums`로 맞추고 오른쪽 정렬(`.num`)한다.

## 3. 색
- 색상 값은 토큰(`var(--accent)` 등)만 쓴다. HEX를 직접 쓰면 색조·포인트색을 바꿔도 그 부분만 남는다. 브랜드 색은 `--accent`로 넣는다.
- 넓은 색면은 `--accent-soft`나 `--surface-2`를 사용해 비교·정보 묶음을 만든다. 진한 색의 면적보다 글자 대비와 시선 우선순위로 판단한다. 밝은 표지는 큰 제목과 주제 이미지를 결합할 수 있다. KPI·결론·발표 순서·설명 본문은 표지에 기본으로 넣지 않는다.
- 긍정·부정 표시는 `.up`/`.down`으로 하고, 색 외에 ▲▼ 기호를 함께 둔다(흑백 인쇄 대비).

## 4. 레이아웃·간격
- 간격은 `--sp-1`~`--sp-7` 토큰을 우선한다. 발표 전용 고정 화면 배치가 필요하면 문서 CSS에서 간격을 정하되 전체 페이지의 정렬과 표시 크기를 함께 검수한다.
- 섹션 사이 간격은 문단 사이 간격의 2배 이상으로 둔다.
- 여백은 A4 기준 좌우 16mm 이상이다. 표지·원페이저·덱처럼 전체를 칠하는 페이지만 `@page { margin: 0 }`을 쓰고, 안쪽 padding으로 여백을 만든다.
- 불필요한 박스 중첩은 피한다. 비교 대상별 카드·수치 영역은 허용한다. 같은 하단 요약이나 차트 옆 상자를 관성적으로 매 장 반복하지 않는다.
- 2~3단 그리드는 `.grid-2`, `.grid-3`을 쓴다. 한 단의 폭이 50mm보다 좁아지면 단 수를 줄인다.

## 5. 페이지 나눔 (인쇄 전용 규칙)
- 제목 바로 뒤에서 페이지가 끊기지 않게 한다(`break-after: avoid`, core.css에 있다).
- 표 행, 카드, 그림, 코드 블록은 `break-inside: avoid`를 적용한다.
- 긴 표는 `<thead>`를 반드시 넣는다. 페이지가 넘어가면 헤더가 반복된다.
- 새 장은 `.page-break`로 시작한다. 빈 페이지가 생기면 앞 요소의 높이를 먼저 의심한다.
- 고정 크기 페이지(`.sheet`, `.slide`)는 `overflow: hidden`이 걸려 있다. 넘친 내용은 **잘려서 보이지 않으므로** 미리보기로 반드시 확인한다.

## 6. 이미지·차트
- 차트는 인라인 SVG나 고해상도 PNG(2x)를 쓴다. 텍스트를 이미지로 넣지 않는다.
- 선택한 그림과 표에는 읽는 기준을 설명한다. 자산 원본과 기준일은 별도 제작 메타데이터에서 관리한다. 특별히 요청하지 않은 ‘출처’ 라벨·출처 푸터·참고자료 페이지를 자동 추가하지 않는다. 표 캡션은 표 위에 표시된다(페이지 경계에서 표와 떨어지지 않게 하기 위함).
- 로컬 이미지는 HTML 기준 상대경로를 쓴다. 절대경로(`/Users/...`)는 쓰지 않는다.

## 7. 콘텐츠
- 사용자 제목 지시를 먼저 따른다. 디자인만 요청하면 원문 제목을 유지한다. 새 문서를 작성할 때는 주제형·발견형 중 사용자의 예시와 자료에 맞는 형식을 쓴다. 한국어 제목은 존댓말 종결(`~합니다/~됩니다/~입니다/~습니다`)과 끝 마침표를 피한다. 예: "매출 분석" 대신 "신규 채널 매출 비중 38%".
- 불릿·통계·라벨처럼 문장 조각인 항목은 불필요한 끝 마침표를 생략한다. 완전한 설명 문장에는 자연스러운 문장부호를 쓴다.
- 불릿 한 항목은 두 줄 이내로 쓴다. 불릿이 6개를 넘으면 묶거나 표로 바꾼다.
- 사용자가 준 수치만 쓴다. 예시 수치를 지어내 실제 데이터처럼 넣지 않는다. 템플릿의 자리표시 문구는 전부 교체하거나 삭제한다.

## 8. 목적과 반복으로 보는 디자인
`anti-ai-design.md`에 따라 목적 없는 반복을 검토한다. 위계는 크기·굵기·여백·색면·비교 배치로 만든다. 장식이 적다는 사실만으로 좋은 디자인으로 판정하지 않는다.

## 9. 렌더 후 체크리스트
미리보기 PNG를 **모든 페이지** 직접 열어 보고 확인한다.
- [ ] 페이지 수가 의도와 같다(`--expect-pages`).
- [ ] 잘린 텍스트, 겹친 요소, 빈 페이지가 없다.
- [ ] 제목만 페이지 끝에 남아 있지 않다(고아 제목).
- [ ] 한글이 □(두부)로 깨지지 않는다.
- [ ] 페이지 하단에 3줄 미만만 걸친 문단이 없다.
- [ ] 템플릿 자리표시 문구("보고서 제목", "조직명" 등)가 남아 있지 않다.
- [ ] 러닝 헤더(`@top-right` content)를 실제 문서 제목으로 바꿨다.
- [ ] 색 대비가 충분하다. 회색 글자가 흰 배경에서 흐리지 않고, 어두운 면(표지·히어로·사이드바) 위 글자가 잘 보인다.
- [ ] 강조 카드(`.card.hl`)와 콜아웃의 글자가 배경에 묻히지 않는다.
- [ ] `render`가 출력한 `디자인:` 설정이 사용자가 고른 안과 같다.
- [ ] 디자인 경고를 검토하고, 유지한 표현의 정보 역할을 설명할 수 있다.
- [ ] 전체 축소판에서 표지·근거·비교·결론의 역할이 보이고, 같은 배치가 관성적으로 반복되지 않는다.
- [ ] 모든 페이지의 PNG 내부 축·범례·핵심 숫자를 확대 없이 읽었다. 컨택트시트만 본 경우 개별 페이지 판독 완료로 기록하지 않는다.
- [ ] 원본 그림의 본편·부록·미사용 목록과 페이지별 시각 검수 기록이 실제 PDF와 일치한다.

## 전체 발표 디자인과 편집성

참고 PDF가 있으면 `visual-storytelling.md`에 따라 모든 페이지를 펼쳐 본 뒤 대표 페이지를 실제 크기로 대조한다. 그래프/도형의 개수, 팔레트 변경, 카드 삭제만으로 디자인 완성도를 판단하지 않는다. 제목의 위치·무게, 증거의 면적, 정렬축, 여백 간격, 밀도의 변화와 표지-본문-결론의 연결을 함께 본다. 사용자가 디자인만 요청하면 내용 평가는 범위에서 제외한다.

편집용 발표는 `editable-presentations.md`에 따라 PPTX와 같은 정본에서 출력한 PDF를 전달한다. 코드/HTML만 전달하거나 슬라이드를 통째로 이미지화하지 않는다.
